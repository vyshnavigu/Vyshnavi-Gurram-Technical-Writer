UX Writing Case Study

Helping Users Catch Email Typos Before Login Verification

by Vyshnavi Gurram, Technical Writer

On this page

This case study reviews a login flow on ChatGPT.com. A typo in the email domain was accepted, and the flow moved to a verification screen that said a code had been sent to the entered address. I reviewed the flow to identify where clearer messages could help the user correct the email before continuing.

Case Summary

Product areaChatGPT.com login
User actionEntered sample.user@examplec.om instead of sample.user@example.com
Observed issueThe flow continued to the verification screen without warning that the domain looked incorrect.
UX goalHelp the user identify and correct a likely typo while the email field is still editable.
Scope of this review

This is an independent UX writing review of an observed flow, not a change implemented by the product team. Screenshots use anonymized sample email addresses. The proposed messages and checks have not been tested with users.

Evidence from the Flow

The following anonymized screenshots show the typed address in the login form and the verification screen displayed after continuing.

Steps to Reproduce

  1. Go to ChatGPT.com and open the Log in or sign up dialog.
  2. Enter sample.user@examplec.om in the email field.
  3. Select Continue.
  4. Observe that the flow moves to the Check your inbox screen.
  5. Observe that the screen asks for a verification code sent to the mistyped email address.

Observed Behavior vs. Expected Behavior

Observed behaviorExpected behavior
The login process continues when the domain contains a likely typo.The form should warn the user before moving to verification.
The verification screen states that a code was sent to the entered address.The flow should help the user correct the email first and then confirm the accepted address.

UX Writing Issue

The issue is not only about form validation. It is also about what the page tells the user. The verification message confirms the next step without helping the user notice a likely mistake in the address. The user may believe the inbox is the problem rather than the email they entered.

The better moment to help is before verification, when the address is visible and easy to edit.

Why This Matters to Users

  • The user may wait for a code that never arrives.
  • They may select Resend email and repeat the same problem.
  • They may believe the product is not working.
  • They may switch to another login method unnecessarily.
  • Repeated confirmation without a useful next step can reduce trust.

Suggested Flow

1
Enter email

The user types an email address in the login form.

2
Check format and domain

Check for common domain typos before advancing.

3
Show inline guidance

If a likely typo is detected, show a clear message next to the email field.

4
Allow correction

The user edits the address or chooses a suggested correction.

5
Proceed to verification

After the corrected address is accepted, send the code and show the accepted address.

Suggested UX Copy

Use direct wording that explains the problem and gives the user an immediate action.

MomentCurrent experienceSuggested copy
Email field after ContinueNo warning before verification“This email domain does not look valid. Check the spelling before continuing.”
Typo suggestionNo suggestion shown“Did you mean sample.user@example.com?”
Primary actionContinueUse suggested email
Secondary actionNot shownEdit email
Verification screen after correctionDisplays the mistyped address“Enter the verification code we sent to sample.user@example.com.”

Alternative when the domain check cannot verify the address

We could not verify this email domain. Check the spelling or try another sign-in method.

Issue Report Version

This is the concise issue summary I would send to a product, UX, or engineering team.

TitleLogin accepts an email address with a typo in the domain and proceeds to verification.
StepsOpen login, enter sample.user@examplec.om, and select Continue.
ObservedThe flow moves to the verification screen and says a code was sent to the entered address.
ExpectedThe login form should flag a likely domain typo before advancing.
Suggested fixCheck for common domain typos and display an inline message with a clear correction option.

UX Writing Principles Used

  • Catch the issue early. Show guidance before the user reaches a dead end.
  • Be specific. Name the email domain rather than saying “Something went wrong.”
  • Use neutral language. Say “Check the spelling” rather than blaming the user.
  • Provide a next action. Offer an edit option or a suggested correction.
  • Avoid premature confirmation. Do not present success as certain when the flow has not confirmed deliverability.

Reflection

A login error at the beginning of a user journey can prevent everything that follows. In this example, a short, timely message could help the user correct the address without waiting for a code that may not arrive.

The proposed improvement combines UX writing with validation behavior. It would need implementation and usability testing before its effectiveness could be measured.
